⚡ Ahorro de Tokens

RTK: El Compresor de Consola para Agentes de Código

Evita que la salida masiva de `npm install`, `pytest` o `git status` queme la ventana de contexto.

❌ Sin RTK (Terminal Cruda)

• `npm test` devuelve 250 líneas con warnings irrelevantes (8.000 tokens).
• La sesión se satura en 3 comandos.
• El agente olvida el objetivo principal de la tarea.

✅ Con RTK (`rtk-ai/rtk`)

• Intercepta y resume: solo extrae el stacktrace del error y el exit code (150 tokens).
• -70% a -85% de ahorro de tokens por sesión.
• Mantiene la memoria limpia para resolver el bug.

Repositorio: `rtk-ai/rtk` • Nota: [[05 - RTK]]Slide 3 / 5
📋 Desarrollo Guiado

Spec Kit de GitHub: Desarrollo Guiado por Especificaciones

El estándar formal para que los agentes construyan features complejas paso a paso.

1. /spec.md

Documento exhaustivo de requerimientos funcionales, contratos de entrada/salida y dependencias.

2. /plan.md

Desglose atómico de tareas secuenciales con checklist de verificación previa.

3. /tasks.md

Ejecución incremental archivo por archivo con validación de tests antes de avanzar.

🎯 Buenas Prácticas

Reglas de Oro para Vibe Coding Profesional

Cómo mantener la salud del repositorio mientras los agentes generan código.

1. Commits Atómicos

Hacer commit tras cada feature completada con mensajes semánticos (`feat:`, `fix:`).

2. Hooks de Linting

Ejecutar linters automáticamente para que el agente no deje sintaxis rota.

3. Diffs Verificados

Inspeccionar siempre el `git diff` antes de fusionar ramas a producción.
