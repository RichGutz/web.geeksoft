El Dilema del Retrieval en Codebases: ¿Por qué Falla el RAG Tradicional?

Por qué los embeddings densos solos no bastan para buscar código fuente
GEEKSOFT ACADEMY
❌ El Fallo del Dense Search Aislado

Los embeddings vectoriales entienden semántica, pero fallan rotundamente con identificadores exactos:

  • Si buscas authenticate_jwt_token(), el embedding denso puede devolverte un archivo de hashing genérico porque "hablan de seguridad".
  • No distingue entre nombres de variables críticas como is_admin vs is_active.
✅ La Solución: Fusión Híbrida RRF (Dense + BM25)

RepoLens combina lo mejor de ambos mundos:

  • BM25 (Sparse): Atrapa símbolos exactos, nombres de funciones y variables.
  • Dense (Vector): Atrapa intenciones conceptuales (*"mecanismo de reintentos con backoff"*).
  • RRF (Reciprocal Rank Fusion): Intercala y re-ordena con la fórmula $1 / (60 + r_m(d))$.

🔌 Servidor FastMCP Desacoplado

El servidor expone herramientas universales JSON-RPC 2.0:

list_repository_tree(owner, repo, branch)
read_file_content(owner, repo, path)
semantic_code_search(query, repo_id)

Cualquier agente externo (Claude Code, Cursor, Antigravity) puede conectarse directamente a repolens-mcp-16hr.onrender.com.

🧠 LangGraph State Machine

Orquestación conversacional con estado persistente:

  • Multi-Thread Sessions: Mantiene sesiones de auditoría independientes por repositorio.
  • Memoria Contextual: Recuerda qué archivos ya fueron explorados para evitar lecturas redundantes.
  • Inferencia Groq: Generación a +500 t/s para interacción fluida en tiempo real.
