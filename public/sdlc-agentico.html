⚡ Cambio de Mentalidad

De "Programador Aislado" a "Director de Fábrica Agéntica"

El Vibe Coding simple satura el contexto. La ingeniería agéntica moderna desacopla roles y delega ejecución.

❌ Enfoque Tradicional / Vibe Coding Básico Cuello de Botella

• El humano programa frente al teclado mientras el LLM autocompleta.
• Toda la discusión y código se mezclan en una sola sesión (+100K tokens basura).
• El programador revisa manualmente cada línea: fatiga cognitiva inmediata.
• Alucinación recurrente de APIs y pérdida de coherencia arquitectónica.

✅ Enfoque Multi-Agente / Harness Engineering Escalabilidad 10X

• El humano actúa como Sponsor / Revisor de Gates definiendo objetivos.
• Contexto Aislado: Cada agente solo recibe lo que necesita para su tarea atómica.
• Sustrato en Archivos: La comunicación ocurre vía `PRD.md`, `openapi.json` y `test_report.json`.
• Verificación Determinista: Suites de tests en Docker (`pytest`) validan el éxito o fallo.

Principio: "Los agentes no improvisan: siguen Procedimientos Operativos Estandarizados (SOPs)." Slide 2 / 10
👥 Estructura de Equipo

Los 5 Roles Agénticos del SDLC y sus Contratos de Salida

Separación estricta de responsabilidades para garantizar coherencia y evitar el sesgo de auto-aprobación.

👩‍💼 1. Product Manager Fase Diseño

Input: Prompt humano.
Output: `PRD.md` con historias de usuario y criterios de aceptación.

🏗️ 2. Architect Lead Fase Blueprint

Input: PRD aprobado.
Output: Diagramas Mermaid + Topología + Esquemas de Datos SQL/Pydantic.

💻 3. Engineer Squad Fase Coding

Input: Especificación técnica.
Output: Código modular Frontend/Backend + Dockerfile.

🔍 4. QA Auditor Fase QC

Input: Código + PRD.
Output: Suite de pruebas en Sandbox + `test_report.json` (100% PASS).

🚀 5. DevOps Release Fase Deploy

Input: Código aprobado.
Output: Contenedor en VPS + SSL Let's Encrypt + Smoke Tests.

Regla de Oro: "El agente que programa NUNCA debe ser el que aprueba el Control de Calidad." Slide 3 / 10

📋 Plan de Acción

Checklist Operativo para Lanzar tu Fábrica Agéntica

Guía de 6 pasos para entregar requerimientos y recibir software verificado en producción.

1. Briefing de Alto Nivel

Define el QUÉ y el PARA QUÉ en 3 párrafos. Deja el CÓMO técnico al agente arquitecto.

2. Revisión de Diagramas

Verifica visualmente los diagramas Mermaid (Gate 1). Aprueba la topología antes de compilar.

3. Aislamiento por Módulos

Asigna tareas atómicas a programadores agénticos independientes sobre contratos tipados.

4. Suite QC en Docker

Exige al menos un 90% de cobertura de pruebas unitarias y de integración en sandbox.

5. Auto-Fix Supervisado

Permite un bucle de corrección autónomo limitado a un máximo de 3 iteraciones.

6. Despliegue con SSL

Publicación automática en VPS vía Traefik/Docker con health check `200 OK` verificado.
